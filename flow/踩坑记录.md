# 踩坑记录

- **GPIO0 不是产品键**：它是 BOOT0/下载入口。任何「S5=GPIO0」的旧说法都已作废，按键只用 S1–S8（GPIO2/47/38/41/1/6/7/48）。
- **GPIO8 共享电源域时序**：WS2812(GPIO12)、麦克风(GPIO9/10/11)、扬声器(GPIO14/13/15)、绿灯(GPIO42) 都挂在 GPIO8 后。必须在构造 `CircularStrip`、启动 I2S 之前拉高 GPIO8 并等电源稳定，否则外设上电即乱。
- **烧录流程**：当前板是「开机态短按一次 BOOT 即进下载模式」，不是「按住 BOOT 再上电」；板上无独立 RESET 键。错误流程会让用户卡住。
- **Flash/分区默认值**：根 `sdkconfig.defaults` 已默认 16MB Flash，分区表 `partitions/v1/16m.csv` 在仓库根（构建时生成，main/ 下没有该目录）。config.json 不要重复写，避免写错路径导致构建失败。
- **NoAudioCodec 变体选择**：该板麦/扬声器时钟独立 → 用 `NoAudioCodecSimplex`（8 参）；`NoAudioCodecDuplex`（6 参，单总线）不适用。
- **Knob 只有 A/B 两相**：`Knob(pin_a, pin_b)` 不含按压脚；编码器按压 S9(GPIO18) 需另建 `Button`。
- **音量接口**：`Application` 无 SetVolume；音量走 `AudioCodec::SetOutputVolume(int)`，需在板内持有 codec 指针从编码器回调调用。
- **IDF v6.1 移除 legacy ADC 驱动**：`#include <driver/adc.h>` 不再存在（被 `esp_adc/adc_oneshot.h` 等取代）。xiaozhi 板子代码若只用 `AdcBatteryMonitor`，**不要**自己 include `driver/adc.h`；`ADC_UNIT_1`/`ADC_CHANNEL_x` 枚举由 `adc_battery_monitor.h`→`adc_battery_estimation.h` 间接引入（官方 electron-bot 板即如此）。直接删掉多余 include 即可。
- **IDF v6.1 GDMA API 改名**：`managed_components/78__uart-uhci/src/uart_uhci.cc` 调用的 `gdma_get_alignment_constraints(chan, *int_align, *ext_align)` 已改为 `gdma_get_channel_alignment_constraints(chan, gdma_channel_alignment_info_t*)`（单结构体，含 `int_mem_alignment`/`ext_enc_mem_alignment`/`ext_no_enc_mem_alignment`）。这是 xiaozhi 上游组件与 v6.1 的兼容坑，本地改 `managed_components/` 可解锁编译；重跑 `idf.py update` 可能被覆盖，应反馈上游修。
- **IDF v6.x 不支持 Git Bash(MSys)**：`idf.py` 必须在 PowerShell/cmd 里先 `. $IDF_PATH/export.ps1` 再跑；非交互 PowerShell 跑 `idf.py` 会报"Python environment not configured to handle Unicode characters"→ 设 `$env:PYTHONUTF8='1'` 绕过。
- **esptool 在 PowerShell 里 `@flash_args` 会被吞参数**：`@flash_args` 被 PowerShell 当成未定义变量的 splatting，esptool 收不到任何地址/文件参数（报 Missing argument，`EXIT=2`，**不写 flash，安全**）。正确写法：先 `Get-Content flash_args` 把每行按空白拆成扁平 token 数组，再用 `@tokens` splat 传给 `write-flash`。
- **乐鑫 USB-Serial-JTAG PID_1001 下载/运行共用**：该设备的 ROM 下载模式和 App 运行模式都枚举为 `VID_303A&PID_1001`，**不能靠 PID 判断板子是否启动**。判断方法：读串口（COM15 原生 CDC / COM11 CH340 UART）看有无 `I (毫秒) ...` 应用日志——有即正常运行，空日志即仍在下载模式（BOOT 未松开，需松开后复位）。
- **烧录后硬复位会重新进下载**：`--after hard-reset` 复位后若 BOOT 仍被拉低，板子重新进下载模式、应用起不来；务必在烧录结束/复位前松开 BOOT 键。
- **esp-idf-cy 的 `idf-env.sh` 在 Windows 有路径 bug**：它把 argv 临时文件拼成相对/legacy 路径导致 esptool 拉不起来（只读验身阶段暴露）。绕过：直接用 IDF venv 的 `python -m esptool ... chip-id`（只读、不写 flash）验身；结果不受影响。此 bug 应反馈 skill 作者。
- **无屏板必须提前 `lv_init()`（真机崩溃复现与修复）**：板子连上 WiFi 后 `starting -> activating` 即崩溃，`LoadProhibited / EXCVADDR=0x14`。用 ELF 反解 backtrace 定位为：`Assets::LvglStrategy::Apply`(assets.cc:291) → `LvglCBinFont::LvglCBinFont`(lvgl_font.cc:6) → `cbin_font_create` → `lv_malloc` → `lv_tlsf search_suitable_block`（TLSF 控制块为空指针）。
  - **根因**：`HAVE_LVGL` 默认就是 1（`display.h`：`#ifndef CONFIG_USE_EMOTE_MESSAGE_STYLE` 才不定义），`Assets` 因此走 `LvglStrategy`；而 `lv_init()` 只被显示驱动（`custom_lcd_display.cc` 等）调用。本板无屏 → 没人初始化 LVGL → 但 `LvglStrategy::Apply` **先构造字体、后判断 display**，于是踩空。
  - **不能靠 `display == nullptr` 兜底**：`Board::GetDisplay()` 默认返回静态 `NoDisplay`，永远不是 nullptr；该判空分支实际不生效。
  - **修法（板内一行）**：在板子构造函数最前面调用 `lv_init()`（用 `lv_is_initialized()` 防重复，`lv_init()` 自带"已初始化则跳过"保护），并 `#include "display.h"` 取得 `HAVE_LVGL`/`lvgl.h`。副作用：LVGL 会从 PSRAM 取 1MB 池（`CONFIG_LV_MEM_SIZE_KILOBYTES=1024`，经 `lvgl_psram_pool.h`），本板 8MB PSRAM 可接受。
  - **`CONFIG_USE_EMOTE_MESSAGE_STYLE` 不可用**：它在 Kconfig 里 `depends on` 仅限 5 块官方板（ESP32_S3_BOX / VOCAT / LICHUANG_DEV_S3 / RYMCU_BIGSMART / SENSAIRSHUTTLE），且会把 assets 分区切成 expression 分区，不适合当"无屏开关"。
  - **方法论**：拿到 `Guru Meditation` 日志先别猜，用 `xtensa-esp-elf-addr2line -pfiaC -e build/xiaozhi.elf <backtrace地址>` 直接反解到源码行，一次定位（本次省掉多轮试错）。
